# Governance

Atap is a small project with one maintainer, Aniq Najmuddin ([@anake-an](https://github.com/anake-an)).

## How decisions are made

- The maintainer makes the final call on scope, design and releases.
- Discussion happens in issues, pull requests and GitHub Discussions. Good arguments and clear use cases carry the most weight.
- Large changes should start as an issue, so the direction is agreed before code is written.
- Every change goes through a pull request and must pass CI. The maintainer reviews it before it merges.
- The [low-resource rule](CONTRIBUTING.md#the-low-resource-rule) and the [privacy promise](PRIVACY.md) are fixed. A change that breaks either will not be merged.

## Contributors

Anyone can contribute under the [MIT license](LICENSE). Contributors follow the [Code of Conduct](CODE_OF_CONDUCT.md). If the project grows, the maintainer may invite regular contributors to review pull requests. This page will change when that happens.

## Releases and security

The release steps are in [docs/RELEASING.md](docs/RELEASING.md). Security reports follow [SECURITY.md](SECURITY.md).
